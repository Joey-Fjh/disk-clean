# Disk Clean — Agent 驱动产品方案

> **文档性质**：已确认的目标产品方案（设计基线）

> **当前代码状态**：阶段 0–2 已落地（统一扫描 + Candidate 判断模型）；**尚未接入 Agent / LLM**（见 [README](../README.md)）

> **最后更新**：2026-08-24
---

## 1. 产品定位

**Disk Clean** 是一个 **Agent 驱动的 Windows 磁盘清理小工具**。

它把「扫描磁盘 → 调查空间占用 → 判断是否值得清理 → 生成方案 → 用户确认后执行」这一完整过程，做成**可视化、可重复运行**的独立桌面工具。

核心承诺：

- **不依赖**外部 Codex、Cursor 或其他 Agent 应用。
- **不宣传**「AI 自动删除」；推荐界面文案为：**「Agent 自动分析并制定清理方案，由你确认后安全执行。」**
- 模型负责**建议**；本地程序负责**允许执行什么**——二者职责分离，不可混淆。

### 与当前实现的关系

| 维度 | 当前已实现（规则驱动 v0.x） | 本方案目标 |
|------|---------------------------|-----------|
| 扫描发现 | 统一扫描：空间发现 + 规则识别 | 渐进式空间扫描，统一为流程前置 |
| 清理判断 | Candidate 模型：`pending`（空间发现）+ legacy 规则 `suggested`/`caution`；**尚无 Agent** | **Agent 作为主要判断者**，综合扫描信息与本地证据形成清理建议 |
| 空间分析 | 已并入统一扫描，显示为「待判断」 | 统一清理流程的前置节点 |
| 本地规则 / JSON | 规则即扫描与授权基础 | **识别证据、保护信息与经验提示**；不是主要决策入口 |
| 模型 | 无 | 用户自备 API Key，主进程管理 |
---

## 2. 第一性原理

```
磁盘扫描负责发现空间占用
    ↓
本地规则、通用特征与 JSON 经验提供识别证据、保护信息与快速提示
    ↓
Agent/LLM 作为主要判断者，综合上述信息形成统一清理建议
    ↓
用户负责最终确认
    ↓
本地受限工具负责安全执行
```

角色划分：

| 角色 | 职责 |
|------|------|
| 扫描器 | 发现占用、生成目录摘要与会话快照 |
| 本地规则 / 特征 / JSON | 提供证据与经验，**不替代** Agent 成为目标产品的主要决策入口 |
| Agent / LLM | **清理方案的主要判断者**——综合扫描信息与本地证据，形成整体建议 |
| 用户 | 接受或拒绝建议、勾选执行范围 |
| 本地程序 | 依据会话候选项与安全策略决定**是否允许执行** |

设计约束：

1. **没有 JSON 时，Agent 驱动流程仍然成立**——JSON 是可选经验层，不是扫描或判断的前提。
2. **没有模型连接时**，降级为空间展示与本地提示；**不**应描述为完整的 Agent 清理体验。
3. **扫描尽量全面，删除必须保守**——不因引入 Agent 而放松。
4. 执行链路保持：`Candidate → CleanupPlan → SafetyValidator → Cleaner`；Agent 与 JSON 均不得绕过。
---

## 3. 完整用户流程

```
选择全部磁盘或指定盘符
    ↓
开始扫描
    ↓
展示空间分布（磁盘容量、顶层目录占用）
    ↓
本地整理目录摘要（脱敏、聚合统计；附带本地规则/特征/JSON 提供的证据提示）
    ↓
Agent 综合扫描信息与本地证据，形成整体清理判断与建议
    ↓
（可优先深入大型、异常或信息不足的目录，不代表只处理「未知」项）
    ↓
信息不足时 → 继续进行受限、只读调查（可多轮）    ↓
生成清理建议（含理由、影响、把握、预计释放空间）
    ↓
用户确认勾选范围
    ↓
生成 CleanupPlan
    ↓
SafetyValidator 校验
    ↓
移入回收站
    ↓
重新扫描并展示实际结果
```

**重要说明**：

- **「空间分析」不再是独立模式**，而是上述统一清理流程的**前置节点**。用户不再在「安全清理」与「空间分析」之间二选一。
- 当前 UI 中的模式切换（`quick` / `full`）属于**待迁移的旧交互**，不代表目标产品形态。

过程可视化要求：用户能沿链路查看 **扫描发现 → Agent 调查 → 判断依据 → 清理建议 → 用户确认 → 实际执行 → 重新扫描结果**。敏感路径默认脱敏；API Key 永远不进入记录。

## 4. Agent 的权限边界

### Agent 可以

- 查看磁盘概况（容量、已用、可用）。
- 查看目录占用（逻辑大小、项数）。
- 请求继续分析指定目录（通过受限只读工具）。
- 查看文件类型、数量和修改时间分布。
- 查看**有限的**文件名或子目录样本（非全文、非任意深度）。
- 判断内容性质和清理价值。
- 生成清理建议和 CleanupPlan **草案**（须经用户确认与本地校验后才可执行）。

### Agent 不可以

- 获得任意 Shell、PowerShell 或 `cmd` 权限。
- 直接传入任意路径执行删除。
- 绕过用户确认。
- 绕过 `protectedPaths`、扫描会话授权或 `SafetyValidator`。
- 自行扩大已确认的清理范围。
- 仅凭自己的判断解除本地保护。
- 自行读取文件正文（除非未来增加明确授权流程）。

### 职责分离

| 职责 | 承担方 |
|------|--------|
| 「建议清理什么、为什么」 | 模型 / Agent |
| 「允许执行什么、如何执行」 | 本地程序（Plan + Validator + Cleaner） |

模型差异只影响**建议质量**，不能改变**安全底线**。

## 5. 建议清理与执行授权（目标设计，待迁移）

> **当前实现**：`SafetyValidator` **仍要求候选项匹配已启用 JSON 规则**才能进入清理执行。本节描述目标授权模型，**尚未实现**。

通俗总结：

> **Agent 决定建议清理什么；用户决定是否接受；本地程序决定这次操作能否安全执行。**

### 目标原则

1. Agent **可以**判断一个没有 JSON 规则的候选项值得清理，并给出理由、影响与把握程度。
2. 用户确认后，该候选项**可以**申请进入 `CleanupPlan`。
3. 是否允许执行，**不再永久依赖**「必须匹配某条 JSON 规则」。
4. LLM 的建议**不能独自**授予执行权限；用户确认也**不能**绕过本地硬性保护（如 `protectedPaths`）。

### 目标授权依据（须同时满足）

| 条件 | 说明 |
|------|------|
| 有效扫描会话 | 候选项来自**当前有效扫描会话**，非历史或外部输入 |
| 候选项 ID | 使用会话内分配的候选项 ID，**不接受**模型直接提供的任意路径作为执行凭证 |
| 快照一致 | 路径与大小等关键属性仍与扫描快照一致（变化则拒绝或要求重扫） |
| 非受保护路径 | 不在 `protectedPaths` 内 |
| 路径边界 | 不越过符号链接、junction 或解析边界 |
| 白名单动作 | 清理动作属于本地白名单（如移入回收站） |
| Agent 已建议 | 候选项带有 Agent 判断与依据（规则驱动旧候选项在迁移期另见兼容策略） |
| 用户明确确认 | 用户勾选并二次确认 |
| 非「无法确定」 | **无法确定**的项目默认**不可选择清理**（已确认产品决策） |

规则匹配在目标方案中仍可作为**证据与额外约束**，但**不再是** Agent 候选项进入 Plan 的**唯一**凭证。

### 与 JSON 的关系

- JSON **不是**执行的必要条件。
- JSON 提供：已知软件特征、排除项、用户确认后的本地经验——供 Agent 参考，加速识别。
- 无 JSON 时，Agent 仍可基于扫描摘要与只读调查形成建议；能否执行由上述会话授权模型决定，而非「先补一条规则」。

## 6. 模型连接
第一版采用**用户自备 API Key**，在设置页配置：

| 配置项 | 说明 |
|--------|------|
| 服务商预设 | 常见兼容端点模板 |
| 自定义 API 地址 | 支持自建或代理 |
| API Key | 主进程加密存储 |
| 模型名称 | 用户指定 |
| 接口协议 | 如 OpenAI 兼容 Chat Completions |
| 连接测试 | 验证可达性与鉴权 |
| 模型能力测试 | 验证基本推理与结构化输出 |

**参考但不依赖 CC-Switch**：借鉴其 Provider 预设、地址处理、协议兼容、模型映射和连接检测思路；Disk Clean 内置自己的配置与存储，不与 CC-Switch 运行时耦合。

### 第一版明确不做

- 外部 Codex / Cursor 接入。
- OAuth 逆向代理。
- 多工具配置同步。
- 多 Key 轮换与自动故障切换。
- 复杂用量统计与云端同步。

### API Key 安全要求

- 由 **Electron 主进程**管理。
- 使用 **Windows / 系统安全能力**加密保存。
- **Renderer 不得**读取已保存 Key 的明文。
- **不写入**普通 JSON、日志、扫描报告或导出文件。
- 保存后 UI **只显示末尾四位**；只能替换或删除，默认不能重新显示完整 Key。

## 7. 隐私原则
**默认不发送文件内容。**

允许发送给模型的信息限于：

- 脱敏后的目录信息。
- 逻辑大小。
- 文件和目录数量。
- 扩展名分布。
- 修改时间分布。
- 必要的有限层级结构。
- 本地识别出的特征（如「疑似浏览器缓存目录」）。

默认隐藏用户名和敏感路径片段。

**不可信输入处理**：文件名、目录名和文件内容都必须视为不可信数据，**不能**作为 Agent 指令执行（防提示注入）。

---

## 8. 渐进式扫描

默认扫描**全部本地磁盘**，但不能每次递归读取所有文件。

建议过程：

1. 获取磁盘容量概况。
2. 统计顶层目录占用。
3. Agent 可**优先**深入大型、异常或信息不足的目录——这是调查**策略**，不代表 Agent 只负责「未知」或未匹配规则的目录。
4. Agent 根据现有信息决定是否请求继续深入。
5. 支持**取消**、**增量结果展示**和**继续分析**。
6. 切换模型或模型暂时失败时，**复用已有扫描结果**，不强制重新扫盘。

阈值（大小、深度、样本数等）只控制**扫描深度、分析优先级和展示**，**不直接授予清理权限**。

## 9. 结果设计

### 统一结果分档（目标 UI）

| 分档 | 含义 | 与当前实现的对应关系 |
|------|------|---------------------|
| 建议清理 | Agent 判断为低风险、可重建的清理项 | 近似当前「建议清理」(safe) |
| 需要确认 | 有清理价值但存在使用成本或不确定性 | 近似当前「谨慎处理」(recommended) |
| 空间占用 / 无法确定 | 仅展示占用或信息不足无法建议删除 | 近似当前「仅分析」(dangerous) + 未识别目录；**默认不可勾选清理** |
> 分档名称与内部 ID 在开发阶段可再对齐；上表仅说明迁移意图。

### 每个 Agent 建议必须说明

- 内容**可能是什么**。
- **为什么**建议清理或保留。
- **预计释放空间**。
- 清理后的**影响**。
- 判断**把握程度**（高 / 中 / 低或等价表达）。
- **使用了哪些信息**（可审计、可理解）。

### 界面文案原则

- 推荐：**「Agent 自动分析并制定清理方案，由你确认后安全执行。」**
- 避免：**「AI 自动删除」**、「一键智能清理」等暗示无需确认的表述。

## 10. JSON 的新定位

JSON（含现有 `config/rules/` 与用户自定义规则）在目标方案中定位为**本地经验库和证据来源**，用于：
- 特殊软件的已知信息（如某 IDE 缓存路径特征）。
- 用户排除项（「永远不要建议清理此目录」）。
- 用户确认后保存的本地经验。
- 特殊目录识别提示。
- 已注册清理方式的引用（仍须走 Validator）。

### JSON 不能

- 替代 Agent 成为目标产品的主要决策入口。
- 决定扫描是否能够运行（无 JSON 时 Agent 驱动流程仍须成立）。- 包含 `command`、`exec`、`script`、`shell`、`cmd`、`powershell` 等命令字段。
- 绕过安全校验。
- 让模型自行写入并**立即生效**（须用户确认后入库）。

用户保存经验前**必须确认**；模型输出不得直接写入规则库。

### 迁移期说明

当前 `SafetyValidator` **仍依赖规则授权**（见 §5「当前实现」）。迁移期间**不得提前移除**现有规则与校验逻辑；阶段 6 将 Validator 迁移为会话候选项授权模型。详见 [RULES-v1.md](./RULES-v1.md) 顶部说明。

## 11. 失败与降级

| 场景 | 预期行为 |
|------|----------|
| 没有配置 Key | 仍可完成空间扫描与占用展示、本地规则/特征提示；**不**提供完整 Agent 清理体验 |
| Key 无效 | 保留扫描结果；提示重新配置；不丢已发现数据 |
| 模型超时 | 允许重试或更换模型；**不重新扫盘** |
| 模型能力不足 | 更多项目归入「无法确定」 |
| Agent 分析中途停止 | 已完成的结果继续可用 |
| 任意模型错误 | **不得**降低本地安全限制（Validator、protectedPaths 等） |

## 12. 过程可视化
用户应能查看完整链路，并在关键节点看到可理解的状态：

```
扫描发现 → Agent 调查 → 判断依据 → 清理建议 → 用户确认 → 实际执行 → 重新扫描结果
```

要求：

- 调查过程可展示「正在分析哪些目录」「为何需要深入」。
- 建议卡片展示依据摘要，而非仅结论。
- 执行后与重新扫描对比，展示实际移入回收站的空间（逻辑大小估算）。
- 敏感路径默认脱敏；API Key **永远不**进入审计或导出记录。

以下为**实施细节**，不是产品方向分歧；在对应开发阶段确定即可：

| 待定项 | 说明 |
|--------|------|
| 第一版 Provider 预设列表与协议 | 支持哪些兼容端点、最低能力要求 |

- 「无法确定」默认不可选择清理。
