# Disk Clean UX 流程 v1（阶段 7A）

> **产品定位**：Disk Clean v0.1 MVP — 可安装、可日常使用、默认安全、Agent 可选增强。

## 主流程

```text
选择盘符
→ 开始清理扫描
→ 扫描与本地识别
→ 有 Key 时 Agent 智能分析
→ 生成清理建议
→ 用户选择
→ 确认清理计划
→ 移入回收站
→ 自动复核
→ 完成摘要
```

## 任务阶段（用户可见）

| 阶段 | 用户文案 | 说明 |
|------|----------|------|
| 扫描识别 | 正在扫描 / 正在整理 | 空间发现 + 本地规则识别；不展示最终五类结果 |
| 智能分析 | Agent 分析高占用位置 | 无 Key 时跳过或显示本地规则完成 |
| 清理建议 | 分析完成 | 展示五类稳定结果分类 |
| 移入回收站 | 正在移入回收站 | 不确定进度条；禁止重复提交 |
| 自动复核 | 正在自动复核 | 清理后重扫；保留清理摘要 |

顶部 **流程条**（`task-pipeline`）反映当前步骤；无法准确计算百分比时使用 **不确定进度** 样式。

## 结果分类（扫描完成后）

仅展示以下五类（进行中不将「正在识别 / 正在分析」作为永久分类）：

| 分类 | 含义 |
|------|------|
| 建议清理 | 已有可靠授权 |
| 谨慎清理 | 需理解影响 |
| 高风险操作 | 不可批量删除 |
| 空间占用 | 不代表垃圾 |
| 建议保留 | 系统/配置应保留 |

每项卡片展示：

- 名称与路径
- 大小
- **判断来源**：本地规则 / Agent / 本地规则 + Agent / 安全策略 / 空间发现
- 简短原因与风险
- 是否可勾选及原因
- 技术依据折叠在「查看详情」

## 清理确认与结果

- 确认框：项数、估算大小、来源摘要、`requiresAppClosed`、回收站说明
- 执行结果卡：成功 / 部分失败 / 全部失败
- 自动复扫对比摘要；失败可「重新复核」
- **复核语义**（2026-08-31）：
  - 全部成功执行项在复核后消失 → 绿色「清理完成」
  - 已执行但复核仍存在 → 警告色「清理已执行，复核发现项目仍存在」，并提示可能已被程序重新生成
  - 执行阶段 rejected/failed 优先保留既有失败/部分失败语义，不被复核结果覆盖
- 自动复核成功后进入与普通扫描相同的五类结果视图；隐藏进度卡与「正在识别」预览

## 扩展清理识别

- 默认首页 **不展示** 规则开发工具栏
- 仅在 **空间占用** 分类提供次要入口「扩展清理识别」
- 流程：选择样本 → 生成/导入 → 预览 → 保存启用 → 重新扫描
- 界面不出现 RuleDraft、Schema、candidateRef 等内部名词

## 设置页

### 模型连接

每份配置独立卡片：使用 / 编辑 / 测试 / 删除；测试状态仅属于当前卡片。

### 规则与经验

- 内置规则（只读）
- 我的规则（可编辑）
- 安全策略（只读）
- **我的经验**（7B 预留，本阶段不持久化）

## 页面与滚动

- 标题栏 + 主 Tab 固定
- 每个主 Tab 单一纵向滚动容器；隐藏滚动条保留滚轮/键盘
- 结果分类 Tab 可 sticky
- 弹窗内容超高时独立滚动

## 响应式目标

- 1366×768
- 1920×1080
- 窄窗口最小宽度 320px（无横向滚动）

## 安全边界（不可削弱）

- Renderer 不新增路径/Key/清理权限
- Session Cleanup Authorization 语义不变
- protected / TOCTOU / confirmation 不放宽
- 用户与模型文本仅 `textContent`
